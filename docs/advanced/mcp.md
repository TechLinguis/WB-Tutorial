# 给 AI 接外挂：一行配置，WorkBuddy 就能调起 Playwright 这类工具

技能和市场里的连接器，覆盖的是现成的活儿。但如果你要用某个小众服务、或者像 Playwright 这种自动化工具，市场不一定有，这时候就得靠 MCP。

MCP（Model Context Protocol）让 WorkBuddy 接入外部服务暴露的标准化工具和资源。你改个配置文件，就能给它接上新能力。这篇讲怎么加、加完为啥还要"信任"一下。

## 01 MCP 是啥：给 AI 开一扇接外部工具的窗

一句话，MCP 是标准协议，让 WorkBuddy 能调用外部服务提供的工具和资源。连接器是官方的、可视化的接法；MCP 更底层、更灵活，适合你自己接想接的东西。

理解了这个定位，你就知道啥时候该上 MCP：现成连接器没有的，自己配一个。比如你想让它自动跑浏览器测试、或者接公司内部某个没上架的 API，MCP 就是那把钥匙。它把"接外部工具"这件原本要写代码的事，变成改个 JSON。听起来简单，但正是这种"简单"，让普通人也能给 AI 接上原本只有工程师才搞得定的工具。

## 02 配置文件就一个，别手抖覆盖

配置写在 `~/.workbuddy/mcp.json`。重点提醒：加新服务器时，是合并进 mcpServers，不是覆盖整个文件。

我见过有人图快直接重写文件，把之前配好的服务器全干没了。稳妥做法：先读现有 mcp.json，把新条目并进去。宁可慢一步，别丢一窝。这点和写代码一个道理：能增量改就别全量覆写。

## 03 加个服务器，三步走

以 Playwright 为例：查官方文档确认 command/args/env 字段；读现有 mcp.json 合并新条目；写入配置。

写成这样就行：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}
```

照着提供方文档填字段，别猜不支持的参数，错的配置会让服务起不来。我建议每加一个服务器就单独测一下能不能起来，别攒一堆一起配，出问题排查起来头皮发麻。一步一个脚印最稳。

## 04 配完别急着用，还差"信任"这步

很容易踩的坑：写完配置，MCP 不会自动激活。你得去连接器管理页右上角"自定义连接器"，找到那个服务器，点"信任"才启用。

所以如果你配完发现调不动，先别怀疑自己，八成是没点信任。这一步是安全设计，防止随便来个配置就自动跑。习惯成自然，每次配完顺手去点一下，比事后发现没生效再回头找强。

## 05 凭据这事，它比你谨慎

服务要密钥的话，按文档写进 env/headers/args；缺凭据它会主动找你要，再写进去。

别嫌麻烦。密钥这种东西，明着写配置文件本来就有风险，它让你确认再写，是对的。敏感信息，多一道确认少一分泄露。另外提醒，mcp.json 里别把明文密码到处拷，凭据走 env 引用比硬编码稳妥。安全习惯，从配置文件开始养。
