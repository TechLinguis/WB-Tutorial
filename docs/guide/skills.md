# 给 AI 拜个师：装一个技能，它就成了某个领域的老手

很多人用 AI，还停留在"问它一个问题，它编一段答案"。但 WorkBuddy 不一样，你可以往它脑子里塞一本"岗位手册"，塞完它就像在那个领域干了好几年的老手。这本手册，叫技能（Skill）。

技能是 WorkBuddy 能力扩展的基本单元。它把某个领域的知识、工作流、工具调用规范打包好，AI 加载后，表现得就像该领域的专家。下面讲清楚技能从哪来、怎么用、怎么安全装。

## 01 技能是什么：给 AI 一本"岗位手册"

打个比方。通用 AI 像个刚毕业的应届生，啥都懂点但都不精。技能就是培训手册：你给它一份"前端设计手册"，它干活就有模有样；给它一份"PPT 生成手册"，它出的片子就像专人做的。

所以技能的本质，是把人类专家的经验，固化成 AI 能照着执行的流程。

## 02 技能分两层：你的和项目的

- 用户级技能，存在 `~/.workbuddy/skills/`，跨项目通用，装一次到处能用。
- 项目级技能，存在项目里的 `.workbuddy/skills/`，专门给当前团队共享，跟着仓库走。

简单说：个人常用塞用户级，团队规范塞项目级。后者特别适合把公司的流程沉淀下来，新人拉下来就有。

## 03 技能从哪来：内置、市场、导入、自己写

四条路：

内置技能，装软件就带，文档、表格、PPT、PDF 这些常见活都覆盖。推荐市场，一句话就能搜来装，比如"装个股票分析技能"。本地导入，从文件夹或 URL 塞自定义 Skill。自己写，用 skill-creator 把你的可复用工作流沉淀成技能。

我特别推崇最后这条。你折腾出一个好用的流程，不沉淀成技能，下次又得从头调一遍。AI 替你跑一遍，你再替它存一份，这才是越用越顺的滚雪球。反过来，技能不是装得越多越好，堆一堆用不上的，反而让它在匹配时犯迷糊。按需装、定期清，才是正经用法。

第四条最值钱。你折腾出一个好用的流程，别只用一次就丢了，存成技能，下次一句话调出来。

## 04 不用背命令：你说人话它就自动加载

你不用记每个技能叫啥。说"帮我把这张图做成视频特效""审查下这个 UI 的设计"，WorkBuddy 自己匹配、自动加载对应技能执行。

当然也能显式用斜杠命令，比如 /commit 提代码、/polish 做前端优化、/audit 做设计审查。但大多数时候，正常说话就行，它比你懂你要点啥。

## 05 装新技能前，它会先替你"安检"

从市场装、导入、下载新技能时，WorkBuddy 先做安全审计，分三档：

P0 严重，强烈警告，你明确确认才继续；P1 警告，提示风险需确认；P2 安全，正常装。

这里有个坑得提醒：已装技能的日常使用不触发审计，只有新安装、导入时才审。所以来源可信这点，全靠你自己把关。别见个技能就装，来源不明的，再好用也先打个问号。
