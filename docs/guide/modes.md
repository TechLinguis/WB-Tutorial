# 选错模式可能把仓库删了：WorkBuddy 的三种"脾气"你得先懂

同一个 WorkBuddy，你让它"直接干"和"先商量"，出来的结果天差地别。我见过有人随手一句话让 AI 去清理文件，结果它真删了；也见过有人小心翼翼，其实那个任务根本不用确认。区别全在"模式"这两个字上。

WorkBuddy 有三种工作模式，从"你说我做"到"只聊不碰"，覆盖了不同协作需求。选对模式，效率翻倍；选错，轻则返工，重则误删。

## 01 一句话分清三种模式

- Craft（你说我做）：收到指令直接落地，读文件、跑命令、生成内容一并交付。绝大多数任务用它。
- Plan（先想后做）：先给你方案和步骤清单，你确认了再动手。适合高风险、大改动。
- Ask（只聊不动）：只读不写，不碰文件不跑命令。适合咨询、审稿、聊方案。

记不住名字没关系，记住它们的核心区别：一个直接干，一个先确认，一个纯唠嗑。

## 02 Craft：默认就它，你动嘴它动手

这是默认模式。你说"帮我把 src 下的 console.log 去掉"，它直接检索、编辑、回报改了哪些文件，全程不用你插手。

优点是快，省掉来回确认的功夫。但快也意味着，遇到删除、外发这类危险操作，WorkBuddy 会主动弹风险提醒让你确认。它不是无脑执行，该停的地方会停。所以日常放心用 Craft，出红字提醒时别手快点掉。

但我得泼句实话：Craft 再爽，也别拿它去动生产环境、别拿它执行你压根看不懂的命令。它能跑任何你授权的命令，权限越大责任越大。把拿不准的危险操作交给 Plan 先过一遍，是老手和新手之间一道实实在在的分水岭。

## 03 Plan：动大手术前，先让它画张图给你看

重构、迁移、影响范围广的改动，先用 Plan。进入后它会先输出计划、列风险点，等你拍板再执行。

比如"把项目从 CommonJS 迁到 ESM"，这活儿动辄改几百个文件。直接 Craft 干，错了回滚都头疼。Plan 模式下它先把迁移路径和风险摆桌上，你看明白了说"行"，它才动。花三分钟看方案，省三小时擦屁股，这笔账划算。

## 04 Ask：只聊不动，适合纯唠嗑和审稿

学习概念、对比方案、做代码审查讨论，用 Ask。它全程只读，不会偷偷改你文件、不会跑命令。

这点对怕"AI 乱动我东西"的人特别安心。你想跟它探讨"这两个方案哪个好"，又不想它顺手帮你改了代码，切 Ask 就对了。聊完关掉，文件原封不动。

## 05 记不住？三条口诀带走

不确定就用 Craft；改动不可逆、影响大切 Plan；只想问问题、零副作用切 Ask。

切换也简单，输入框附近有个模式按钮，点一下换。或者直接在对话里说"切到 Plan 模式""只聊不动"，它听得懂人话。
